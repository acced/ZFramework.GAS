ZFramework GAS 技能编辑器重构计划

这次重构以用户体验为目标，完全重写 Editor/。设计上参考 UE 蓝图编辑器、UE Montage/Notify 时间轴和团结引擎 AnimGraph 1.0。 要达到的效果是：一个窗口、一个文件、几分钟做出一个带动作的技能；Animator、旧版 Animation、序列帧、Spine 等动画形式通过策略模式统一接入。

1 个窗口
建技能、编时间轴、预览、查错都在同一个编辑器里完成，不用再在 Project、Inspector 和结构图之间来回切换。
1 个文件
技能默认用子资产内嵌自己的效果和动画，同时仍能引用外部共享的效果。
≤ 6 步
做出「带动画的普攻」，现在要 15 步以上（见 §04）。
N 种动画后端
运行期和编辑期各有一个策略接口，新增后端不需要修改编辑器。

范围

本次包含

  • 重写编辑器窗口：技能库、结构图、时间轴、Details、预览、消息日志
  • 动画后端策略化：运行期 AnimationBackend 加编辑期 IAnimationEditorAdapter
  • Spine 适配器：放在独立 asmdef 里，由 versionDefines 控制，装了 Spine 才参与编译
  • 技能模板与新建向导，属性和 SetByCaller 键改成从词表下拉选择
  • 数据模型做小幅、向后兼容的扩展：稳定 ID、子资产、新的轨道类型
  • 集中化的校验系统，同时提供 CI 用的批量校验菜单

本次不包含（保持现有设计取舍）

  • 运行期图解释器：沿用 README 的立场，效果和能力仍是数据资产，图只用来授权和可视化
  • 改动纯 C# Core 的规则语义（Attribute / Effect / Ability / Tag / Cue）
  • 具体的特效、音效实现：预览只通过 Cue 预览钩子调用使用方提供的实现
  • 动画混合、IK 这类姿态编辑：那是 AnimGraph 的职责，GAS 只管「什么时候发生什么」

01现状诊断

现有编辑器共 4 个文件、约 1,570 行。结构图（SkillGraphView / AssetNode）是「已有资产引用关系的投影」，时间轴（AnimationTimelinePanel）是 IMGUI 实现、只能拖时间点的面板。 它的工程质量很扎实：撤销统一走 SerializedObject，连线规则提前校验，拖拽一次正好对应一步撤销。问题出在交互模型上，代码质量没有问题。

#问题具体表现代码位置级别
1图上不能「创建」右键「新建效果资产」只会在 Project 里新建一个文件并打一行日志，用户还要自己从 Project 面板把它拖回端口。图里没有节点搜索面板，从端口拖出连线后也不能就地新建。SkillGraphView.cs:597–613P0
2所有字段都要去 Inspector 改节点上只有一行只读描述（「持续 3s · 修改器 2 个」）。改数值、改标签、改修改器都要双击节点跳到 Project，再去 Inspector 改，然后回来刷新。AssetNode.cs:208–243P0
3属性 ID 是裸 inttargetAttributeId、captureAttributeId、durationAttributeId 在 Inspector 里是数字框。策划必须记住「3 = 攻击力」。SetByCaller 键也是手打的字符串，键缺失到运行期才抛异常。GameplayEffectAsset.cs:13–37P0
4动画只能手打片段名和时长clipName 是字符串，duration 要手填。不能从角色身上枚举可用片段，不能自动读取时长，也看不到动作，只能凭数字去对命中帧。SkillAnimationAsset.cs:57–62P0
5一个技能散成 5 个以上文件能力、消耗、冷却、伤害效果、动画各是一个 .asset，Project 面板里很快就乱了。复制一个技能做变体时，要手动复制 5 个文件再逐个重新连接引用。—P1
6时间轴没有播放和预览没有播放头，不能拖动查看（scrub），不能播放。只有标记点和 Cue 区间两种元素，表达不了「霸体窗口」「连招输入窗口」「这一帧发射投射物」。AnimationTimelinePanel.csP1
7节点不能删除，布局不持久出于数据安全，节点被禁止删除，但这也让「移除一个子效果」只能靠删连线。布局每次按列和行自动摆放，用户拖好的位置一重建就丢了。AssetNode.cs:38–42 · SkillGraphView.cs:20–21P1
8任何改动都整图重建每次写回都执行 DeleteElements(graphElements) 再全量重建。选中状态、视口位置都会丢，节点多了以后会闪。SkillGraphView.cs:84–107P1
9报错打断操作连线被拒时弹模态对话框，需要点「知道了」才能继续。现在没有一个持续可见的错误列表，配置问题只有连线那一刻才会暴露。SkillGraphView.cs:244–257P1
10端口身份靠解析字符串标记点端口名形如「标记 3 · 命中」，靠 TryParseMarkerPort 解析出下标。所以授权数组不能排序，下标一变连线就错位。AssetNode.cs:105–138P2
11没有技能总览一次只能看一个能力。看不到项目里有哪些技能，找不到「谁引用了这个效果」，也没有搜索。SkillGraphWindow.csP2
12动画策略只在运行期IAnimationDriver 已经是策略接口，但驱动由宿主代码手动 new，编辑器完全不知道角色用的是哪种动画，也就做不了片段枚举和预览。Spine 没有实现。AnimationDriver.cs · AnimationDrivers.csP1
保留的好设计：视图是数据的投影（不维护第二份数据），所有写操作都走 SerializedObject 和 Undo，连线规则提前到编辑期拦截，拖拽期间不写数据、抬手时一次提交。新架构把这几条原则提升为框架级约束（见 §05 的 SkillDocument 和 EditCommand），不推倒重来。

02参考借鉴

UE 蓝图编辑器

  • My Blueprint 面板：左侧列出图、函数、变量，可以搜索、拖拽
  • 从端口拖到空白处会弹出已按类型过滤好的节点搜索框，选中后自动连线
  • Details 面板跟随选中项变化；节点引脚上直接内联默认值
  • Compiler Results：持续列出错误和警告，点击跳到对应节点；节点上显示红色角标
  • 注释框（Comment）、重路由点、小地图、书签、按 F 聚焦

UE Montage / Anim Notify

  • 多轨时间轴：动画片段轨、Notify 轨（瞬时点）、Notify State 轨（区间）
  • 视口里实时预览，拖动播放头即时看到姿态
  • 按帧吸附，可调预览播放速率
  • Notify 由类型系统扩展，新的 Notify 类型自动出现在右键菜单里
  • GAS 的 PlayMontageAndWait 加 WaitGameplayEvent：动画事件驱动技能逻辑

团结引擎 AnimGraph 1.0

  • 三栏布局：左侧 Blackboard（Graphs / Parameters），中间是图，右侧 Inspector
  • 节点按类别着色，标题条颜色就是语义，不用读字也能分辨
  • 端口左侧内联常量输入框（Speed = 1，Start Position = 0）
  • 节点内嵌专用可视化（AimOffset 的混合空间网格）
  • Live Link：运行时高亮当前执行状态
  • Script2Function：降低「一个个拖节点」的门槛

参考来源：团结引擎动画系统｜AnimGraph 1.0.0 正式版发布（Unity 中国开发者社区）、UE5 Blueprint Editor / Animation Montage / Gameplay Ability System 官方文档。

借鉴点落地方式不照搬的部分

5时间轴（中下）：多轨序列器，有播放头、播放控制、帧吸附和攻速预览。轨道类型可扩展。
6预览视口（右上）：按当前动画后端采样姿态，支持 scrub，并调用 Cue 预览钩子。
7Details（右下）：显示选中节点或时间轴元素的全部字段，提供属性下拉、标签选择器和数值来源编辑器。
8状态栏和消息页：实时校验结果，点击一条消息会跳到对应的节点或轨道元素。

面板用 UI Toolkit（UXML + USS）搭建，各面板可以折叠，分隔条位置用 EditorPrefs 记住。窗口宽度不足 900px 时，预览和 Details 合并成右侧页签。

04核心工作流对比

场景 A：做一个「带动画的近战普攻」

现在：15 步以上，5 个文件，3 个窗口来回切换

Project：建能力资产→ Project：建 3 个效果资产→ Inspector：逐个填时长、修改器（属性填 int）→ Project：建动画资产→ Inspector：手打 clipName→ 打开 Animator 查看片段时长并手填→ 打开结构图→ 把消耗、冷却、动画拖到端口→ 时间轴右键加标记点，凭数字估命中帧→ 把伤害效果拖到标记点端口→ Inspector：配标签→ 进 Play Mode 看效果，不对就回去改

目标：6 步，1 个文件，1 个窗口

① 新建技能 ▸ 模板「近战普攻」→ ② 选预览角色（自动识别为 Animator 后端）→ ③ 动画轨下拉选 Attack01（时长自动填入）→ ④ 拖播放头看着视口找到命中帧，按 M，事件点自动挂上模板里的伤害效果→ ⑤ 节点或 Details 里改伤害系数、冷却时长→ ⑥ Ctrl+S

场景 B：从现有技能派生变体（「重击」= 普攻 + 更长冷却 + 击退）

技能库右键「普攻」▸ 复制为变体→ 内嵌子资产整体深拷贝，外部引用保持原样→ 冷却节点内联改为 2s→ 从「伤害」的「生效时」端口拖到空白处 ▸ 搜索「击退」▸ 引用外部共享效果

场景 C：换动画后端（Animator → Spine）

工具栏「预览角色」换成 Spine 预制体→ 适配器自动切换为 Spine，片段下拉改为列出 SkeletonData 里的动画→ 时间轴和事件点不变，因为时间都存为秒，命中点按时长等比映射→ 运行期角色身上挂 SkillAnimator 并把 Backend 选为 Spine 即可

05总体架构

采用 Document / Command / View 三层。所有面板都只观察同一个 SkillDocument，所有写操作都封装成 EditCommand，统一处理 Undo 分组、脏标记、增量通知和校验触发。 这样把现有「视图是数据的投影」「写回走 SerializedObject」两条原则固化下来，同时去掉「整图重建」和「面板之间互相调用」的耦合。

06动画策略模式

动画适配拆成两个独立的策略族，二者按 BackendId 配对，但互不依赖：

  • 运行期策略 AnimationBackend：知道怎么在角色身上播放，负责创建 IAnimationDriver。需要打进包里，不能依赖 UnityEditor。
  • 编辑期策略 IAnimationEditorAdapter：知道怎么枚举片段、读取时长、采样姿态，给编辑器选片段和做预览用，只存在于 Editor 程序集。

现有的 IAnimationDriver 契约（时长由调用方下达、时钟以 gameplay 侧为准）保持不变，AnimationTask 也不用改。三个现有驱动原样保留，只在外面包一层 Backend。

namespace ZFramework.GAS.Unity
{
    /// 一种动画形式的播放策略。挂在 SkillAnimator 上，经 [SerializeReference] 多态序列化，
    /// Inspector 下拉里列出所有子类——新增后端不需要改任何已有代码。
    [Serializable]
    public abstract class AnimationBackend
    {
        public abstract string BackendId { get; }
        public abstract IAnimationDriver CreateDriver(GameObject host);

        /// 宿主缺少所需组件时给出可读原因，而不是等到 Play 返回 0。
        public abstract bool Validate(GameObject host, out string error);
    }

    [Serializable]
    public sealed class AnimatorBackend : AnimationBackend
    {
        [SerializeField] private int layer;
        public override string BackendId => "animator";
        public override IAnimationDriver CreateDriver(GameObject host)
            => new AnimatorAnimationDriver(host.GetComponentInChildren<Animator>(), layer);
        // Validate: 缺 Animator / 缺 RuntimeAnimatorController 时报错
    }

    [DisallowMultipleComponent]
    public sealed class SkillAnimator : MonoBehaviour
    {
        [SerializeReference] private AnimationBackend backend = new AnimatorBackend();
        private IAnimationDriver _driver;

        public IAnimationDriver Driver => _driver ??= backend.CreateDriver(gameObject);
        private void OnDestroy() => _driver?.Stop();
    }
}

Spine 后端（条件编译）

// Runtime.Spine/ZFramework.GAS.Unity.Spine.asmdef
//   "references": ["ZFramework.GAS", "ZFramework.GAS.Unity", "spine-unity"],
//   "defineConstraints": ["GAS_SPINE"],
//   "versionDefines": [{ "name": "com.esotericsoftware.spine.spine-unity", "expression": "4.0", "define": "GAS_SPINE" }]
// 没装 Spine 时整个程序集不参与编译，库里不会留下「编不过」的代码。
public sealed class SpineAnimationDriver : IAnimationDriver
{
    private readonly SkeletonAnimation _skeleton;
    private readonly int _track;
    private readonly float _mix;
    private TrackEntry _entry;

    public float Play(string clip, float duration, bool loop)
    {
        Animation anim = _skeleton.Skeleton.Data.FindAnimation(clip);
        if (anim == null) return 0f;                           // 与其他驱动同义：找不到返回 0
        _entry = _skeleton.AnimationState.SetAnimation(_track, anim, loop);
        bool stretch = duration > 0f && anim.Duration > 0f;
        _entry.TimeScale = stretch ? anim.Duration / duration : 1f;  // 时长下达，引擎自行推进
        return stretch ? duration : anim.Duration;
    }
    public void Advance(float t) { }                              // Spine 自己推进
    public void Stop()
    {
        if (_entry == null) return;
        if (_skeleton != null) _skeleton.AnimationState.SetEmptyAnimation(_track, _mix);
        _entry = null;
    }
}

创建与连接

  • Space / 右键 / 从端口拖到空白处：打开 SkillNodeSearchProvider。从端口拖出时只列出该端口能接受的类型，分组如下：
    • 新建内嵌效果 ▸ 瞬时 / 持续 / 永久 / 模板（伤害、治疗、Buff…）
    • 引用项目中的效果 ▸ 模糊搜索资产名和标签
    • 新建动画 ▸ 从当前预览角色的片段列表里选
  • 选中后创建子资产、连好线、节点放在鼠标位置，并立即选中，Details 面板显示新节点的字段，整个过程算一步 Undo。
  • 从 Project 面板或大纲拖资产到端口：保留现有行为；拖到空白处时，能力资产切换为根节点，效果资产在落点创建一个「未连接」的游离节点。
  • 连线规则（消耗必须是 Instant、冷却必须授予标签等）由 PortRules 统一提供。不合法的端口在拖线过程中就变灰，悬停时 tooltip 说明原因，不再弹模态框。

删除语义（替代「禁止删除」）

  • 删除连线：只解除引用，与现在一致。
  • 删除外部引用节点：解除所有指向它的引用，资产文件保留。节点画虚线框，表示它只是个引用。
  • 删除内嵌节点：解除引用并删除子资产。如果它还被其他地方引用，就不删，提示「仍被 N 处引用」并列出位置。
  • 删除根能力节点：不允许，与现在一致。
  • 以上操作全部可以撤销（子资产删除用 Undo.DestroyObjectImmediate）。

布局与导航

  • 节点坐标、注释框、折叠状态存到 LayoutStore，持久化在主资产 importer 的 userData（JSON）里。只在编辑器内存在，不进运行期数据。
  • 没有存过坐标的节点（比如从 Inspector 新挂上的）用 Sugiyama 分层算法自动排在相邻空位；工具栏提供「自动整理」。
  • 小地图、F 聚焦选中、A 显示全部、注释框（C）、重路由点（双击连线）。
  • 增量更新：按 ChangeSet 刷新节点；结构变化时 diff 节点集合，保留选中状态和视口。
  • 复制、粘贴、复制节点（Ctrl+C/V/D）：内嵌节点深拷贝，外部引用节点只复制引用。

「能力设置」页签

能力本身的标签门禁（required / blocked / owned / cancel）字段多、也不适合画成连线，所以放进结构图旁的「能力设置」页签。用 5 个标签选择器分组展示，并提供门禁模拟器：勾选一组「持有者当前标签」，实时显示能否激活以及原因。模拟器直接调用 Core 的 GameplayTagSet 和 GameplayAbilityDefinition 判定逻辑，结果与运行期一致。

09Details 面板与字段编辑

Details 面板用 InspectorElement 绑定选中对象，自动获得 Undo 和多选编辑能力。在此基础上，用自定义 PropertyDrawer 解决「Inspector 不好用」的根源问题。这些 Drawer 同时作用于普通 Inspector，不打开编辑器的人也能受益。

Drawer替代行为
AttributeIdDrawer裸 int 的属性 id从 AttributeCatalogAsset 读取「id ⇄ 名字 ⇄ 分类」，下拉显示「战斗 / 攻击力」。如果 id 不在词表里，标黄并显示原值，不会静默清空。用 [AttributeIdField] 特性标注字段。
MagnitudeDrawer6 个平铺字段一行显示公式：「固定 10」「来源·攻击力 × 1.2 + 5」「调用方·Damage.Scale」。点开后根据 kind 只显示相关字段。
CallerKeyDrawer手打字符串下拉列出项目内已用过的键并支持新建；能力级汇总「本技能需要调用方提供的键」，校验规则据此检查。
TagFieldDrawerTags 包自带的字段标签以条状（chip）显示，可以多选，支持层级搜索；标注由父标签继承来的项。如果 Tags 包已提供选择器就复用，不重复造。
ClipPickerDrawer手打 clipName根据当前预览角色的适配器列出片段（含时长）。选中后可一键同步 duration 和 frameRate；没有预览角色时退回文本框。
ModifierListDrawer默认数组每条修改器一行：「生命 加 来源·攻击力×1.2」，可拖动排序、折叠展开。
AttributeCatalog 是本次唯一新增的项目级配置。它在 Unity 层（编辑期和运行期都能读）提供「名字 ⇄ id」映射，Core 里的 AttributeId 仍是包装 int 的结构体，规则层零改动。另提供「从代码常量生成词表」的菜单：扫描标了 [AttributeCatalogSource] 的静态类（如 README 里的 Attr）。

10预览视口

  • 基于 PreviewRenderUtility 建一个独立的预览场景：实例化预览预制体（项目级默认值，加上每个技能可单独覆盖），提供地面网格和轨道相机（拖动旋转、滚轮缩放、F 聚焦）。
  • 姿态由 IAnimationEditorAdapter.BeginPreview 返回的 IPoseSampler 负责采样，切换后端不影响视口代码。
  • Cue 预览钩子 ICuePreview：使用方按 Cue 标签注册编辑期预览（生成粒子预制体、播放音频剪辑）。没注册的 Cue 在视口左上角用文字提示「Cue.Sword.Trail ▶」，所以缺特效也能对时机。
  • 目标假人（可选）：放一个目标模型，事件点触发时在它头顶飘出「效果名 + 数值估算」，数值估算基于预览属性表。
  • 预览完全隔离：不进 Play Mode，不改场景对象，关闭时 Dispose 恢复原状。

反馈原则

  • 不弹模态框：拒绝的操作在端口上变灰并给出 tooltip；完成的操作在窗口底部弹 2 秒提示（ShowNotification）。
  • 选中联动：技能大纲、结构图、时间轴、Details 四处的选中状态始终一致。
  • 可发现：空状态有引导（「还没有动画 · 从预览角色选择片段」按钮），右键菜单列出所有可执行操作并标注快捷键。
  • 可撤销：每个用户手势正好对应一步 Undo，Undo 名称写成中文动宾结构（「添加事件点「命中」」）。

16风险与对策

风险影响对策
GraphView 是 Experimental API，Unity 后续可能弃用中封装在 GraphPanel 内部，节点和端口规则不依赖 GraphView 类型；关注 Graph Toolkit 的进展，等它稳定后单独评估迁移。
子资产在 VCS 里冲突更集中（一个技能一个文件）中内嵌是默认选项而不是强制；共享效果仍然外置；YAML 合并配置 UnityYAMLMerge；提供「外置」转换作为退路。
Animator 的 BlendTree、子状态机、同步层等情况多中适配器只承诺「状态名、时长、单 Motion 采样」；复杂状态降级处理并给出明确提示，不静默出错。
Spine 版本 API 有差异（3.8 / 4.0 / 4.1 / 4.2）中只支持 4.0 及以上，在 versionDefines 里写明；适配代码只用 AnimationState、TrackEntry、SkeletonData 这些稳定 API。
PreviewRenderUtility 预览和真实场景的光照、后处理不同低预览只用来对时机，不保证画面效果；另外提供「在场景中预览」按钮，在 Play Mode 下用真实 Cue 播放一次。
M5 修改 AnimationTask，可能破坏零分配和重入保证高新数组在构造时预分配；新增重入断言；GC 对照测试纳入验收；M5 单独发版。
工期偏乐观中M0～M3 是 MVP，可以独立交付；M4、M5 分别发版；M6 是可选项。每个里程碑都能停下来，交付的都是可用状态。
Samples/BasicCombat 目前不在仓库里，M3 的验收依赖它中M0 开始前先补回范例（或重建），作为整个重构的基准测试场景。

#问题推荐备选
1技能的效果默认存为子资产还是独立文件？默认内嵌为子资产，共享效果外置；两者可以互转保持全部独立文件，只改编辑器（VCS 冲突最少，但 Project 面板依然杂乱）

3图框架选择继续用 GraphView 并加一层封装直接上 Graph Toolkit（Experimental，API 还在变）；或者自研画布（成本高）
4预览视口做到什么程度？姿态采样 + Cue 文字提示 + 可选 ICuePreview 钩子只做时间轴，不做视口（M3 能省约 1 周，但「对着动作找命中帧」的核心体验会打折）

6是否支持一个技能多段动画（连招三段在同一个技能里）？本次不支持：连招用「连招窗口标签 + 3 个技能」实现，与 UE 的常见做法一致动画轨支持多片段顺序拼接（要改 SkillAnimationDefinition 的数据结构，影响面大）
