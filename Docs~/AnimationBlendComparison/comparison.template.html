混入、混出，到底改变了哪一帧？

同一骑士、同一 Clip、同一机位和时间点。左侧将混入、混出都设为 0，右侧读取生成技能的当前参数。画面由 Unity 逐帧渲染，支持慢放、单帧查看、叠图和差分。

你看不出差别，有代码上的原因。技能编辑器当前直接采样 Clip，不计算状态间混合；示例动作又自带起手、收势，正常混出的姿势差异很小。先看混入，再看「中途打断」，最后用「编辑器采样」核对。

为什么正常播完时差别不大？

骑士的动作在 Clip 内已从待机起手，再收回待机。混出从 AnimationTask.OnEnd() 调用 Stop(blendOut) 后才开始，此时两种姿势已经接近。它没有把 Clip 最后 0.2 秒替换成混出。

为什么打断后的差别更大？

战吼在 0.65 秒举剑时打断。启用混出会从当前姿势交叉淡回原先的 Idle；设为 0 时，驱动只恢复速度，不主动切换状态。生成的骑士 Controller 没有自动退出转换，因此无混出的动作还会继续播放。

编辑器预览为什么完全一样？

PreviewPanel.Sample() 调用 ClipPoseSampler.Sample()，最终只用 AnimationClip.SampleAnimation() 采样该动作。该路径没有读取混入、混出参数。切换到「编辑器采样」可查看实际同帧对照。

这次对比控制了什么？

两侧都从 Idle 的 0.60 秒开始，使用相同相机、材质、光照和 60 Hz 步长。仅修改内存副本的两个混合参数。关闭特效显示以便观察骨骼；剑尖、右手数据来自 Unity Transform，没有人为插值或修饰姿势。
