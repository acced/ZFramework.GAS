# GAS 编辑器五阶段改进：验收记录

编辑器与 PlayMode 回归更新于 2026-11-04；平台测试单独标注。对照[改进方案](EditorImprovementPlan.html)，在 Unity 6000.3.14f1、Windows 10、i5-14400F、RTX 5060 上运行。验证工程是独立的 `GASRefactorValidation~`，引用本仓库的包与测试；BasicCombat 用生成器创建。以下把编辑器、独立播放器和性能测试分开记录。

## 从一个真实技能看改动

在 **Tools → ZFramework GAS → 创建 BasicCombat 示例** 生成示例。双击「斩击」资产，再双击时间轴 **0.36 秒的「命中」**。入口只有一个「调用共享模块」；双击它可以进入「扇形斩击动作」。模块检查 `State.Empowered`，满足时施加强化伤害，否则施加普通伤害。修改选敌或效果后，运行时读取的就是这里编辑的动作列表。

## 五个阶段分别验证了什么

| 阶段 | 验证证据与边界 |
|---|---|
| P1 动画混合 | PlayMode 对实际骨骼取样：从基础位置 2 混到技能位置 6，25% 骨骼遮罩得到 3，接全身技能时过渡中点为 4.5。Section 非连续跳入时，不补发跳过的标记；Generic 惯性过渡在旧片段退出后仍从旧姿势连续衰减。Humanoid、优化骨架或接管根运动时不能使用这条惯性路径，校验提示降级。 |
| P2 动作流程 | 逐个打开生成的五个技能的每个标记，比对节点 ID 与资产中的动作。跨分支移动保留 ID，复制得到新 ID；提取／内联支持 Undo／Redo，重做后共享模块及其参数仍属于独立资产。流程布局保存在编辑器元数据里。 |
| P3 运行时调试 | 在生成的骑士上分别施放普通、强化斩击，验证高亮只经过实际分支。断点快照保留模块动作 ID、调用节点 ID 和等级；运行时窗口可按单位看事件、冻结回看。仅录制当前观察单位，从 16 条按需增长至 4096 条；属性与标签名称按显示需要解析。Unity 在整帧边界暂停，不能冻结同步 C# 调用栈。 |
| P4 预览与表现 | 预览可检查多目标扇形／线形等范围、投射物轨迹、区域周期和动画后的任务。BasicCombat 演示震屏、局部顿帧、全局减速、瞄准和片段替换。测试检查服务正常退出／取消时只释放一次，以及实际切换剑、斧 Animator 状态后命中仍有效。假人预演不模拟项目阵营、遮挡和 AI。 |
| P5 生产工具与平台 | 全局内容搜索、参数引用与拖绑、多文档、布局撤销、动作收藏、快捷键、三方快照 Diff。三方合并按稳定键保留独立修改、列出冲突，可导出快照审查。Playable 降频及平台测试结果见下。 |

## 审计修复：复现与边界

| 问题 | 如何验证 |
|---|---|
| 调试器干扰玩法 | 同时挂一个抛异常的观察者和正常观察者，验证标签授予／移除、施加通知、动作执行及结束回调均完整。错误保存在 `DebugObserverErrors`，调试窗口显示次数、最近异常及可复制的完整堆栈，Console 限频汇报。回归逐个核对本测试观察者的异常对象，不依赖全局次数。断点处理会识别已销毁的 Unity 对象。事件泳道冻结列表时用事件序号重选。 |
| 惯性与骨骼 | 在实际 Animator 上测试第一段从 0 和非零位置进入，读出混合前、中、末的骨骼位置；验证未被片段驱动的挂点仍归脚本控制、混出回到初始姿势。骨骼按实际片段在隔离骨架上的采样结果识别，不依赖场景构建或预制体中的旧路径；显式排除全部骨骼的遮罩保留交叉淡化。运行中的替换片段／新遮罩不再驱动的骨骼也有完整的起点、中间、终点和下一帧断言；另测惯性残差尚在衰减时挂上新骨骼并再次切换，以及仅含身体设置的 AvatarMask。先普通混入再首次惯性跳段／混出，检查回到施放前的静止姿势。连续切换 200 次查看图节点数是否有界。 |
| 调度与根运动 | 根运动播放时逐帧检查移动适配器回调，Stop 后检查同一图仍求值但不再移动。默认错相无需项目自定义策略；每个驱动独立处理策略或求值异常。普通 LateUpdate 可在调度器之后读取技能姿势。 |
| 模块与 Undo | 仅通过效果 Magnitude 引用参数：提取后实际施放仍使用原值，重映射并内联后改用调用者的值，共享效果仍是同一资产。校验按引用位置和模块作用域检查。提取把选中动作独占的效果及子效果转移到模块，不留原件；只提取部分共用者时，指出仍引用它的动作所属资产，不落盘。内联及跨文件粘贴只处理新增动作，目标文件拥有私有效果副本，独立效果仍为同一资产。真实域重载后，两层嵌套模块连续两轮 Undo／Redo，逐步核对文件、效果归属、调用和 GUID。复制技能后撤销提取保留被引用的模块；重做遇到路径或 GUID 占用时保留占用者并重接调用，包括外层模块改路径时的内层调用。无参数内联经 Undo／Redo、删除原模块及重新导入后，目标技能里的两个动作仍引用同一份私有效果。 |
| 动作约束与参数统计 | 独立命中／取消回调沿模块调用复用构建器的归属校验；等待、能力归属任务和旧任务执行器会被拦住。同一作用域的重复动作 ID／别名无效，不同调用可以复用同一模块。编辑共享模块只沿直接调用索引传递深度和归属约束；校验前核对已知资产的实际直接调用边；即使调用方未打开、直接改数组或用 ApplyModifiedPropertiesWithoutUndo 重定向到另一个模块，仍能拦住非法 Wait。Undo 不丢弃整个索引。调用方无关分支的坏数据不阻断编辑。错误标明调用方路径和调用 ID。统计参数引用时只计绑定的调用方，不把模块形参当作额外使用。 |
| 混合、替换与表现轨 | Animator 在切换中再次进入相同目标时重新定位；测试检查重播和 Seek 的实际归一化时间。Back 型曲线在界面标明权重限幅。装备覆盖优先，不能用于该后端的空覆盖继续向下查。顿帧影响施法者及命中目标；BasicCombat 的全局减速在释放时保留外部时间倍率的变化。未找到对应表现服务时显示提示，场景仍可在施放时注入。 |
| 预演与真实玩法 | EditMode 用真实 SphereCollider／TargetSearcher 对照圆、扇、线查询的命中和未命中；在 t=0 瞄准第 4 个假人时命中为零，确认未执行备选范围分支；用无动画技能分别执行条件两支，对照真实投射物命中的假人。预演按球形代理和离散轨迹估算，自定义外观不改变代理几何；不模拟动态物理、项目阵营或 AI。 |
| 编辑器呈现 | 上方两图为修复后的 Unity 窗口。节点与端口文字加大，分支尽量复用父行；默认假人为小球。短表现区间的名称放到轨道头，条宽保持实际时长。普通时间调整不重建流程节点。 |

## 2026-11-04：共享效果和技能独占骨骼

- 私有效果跨文件粘贴或内联时可取消以保留共享。明确选择独立副本后，先后复制的两个动作在目标文件复用同一个效果。生成/撤销模块共用一份按资产导入增量维护的反向依赖索引；检查精确到子资产引用。已验证自定义 SO（含直接赋值但尚未标脏的引用）、Prefab、已关闭场景中任一处直接引用私有效果均阻止移动；只引用宿主技能的 SO 不阻止提取。原生二进制场景只能确认文件依赖时，保守保留。
- 移动前列出原 GUID:fileID；本编辑器转移节点位置和折叠信息。外部系统用字符串保存的键不承诺自动替换。当前 Unity 版本上，经过真实域重载、两轮嵌套撤销，分别核对恢复到技能和外层模块的原 GUID **及非零 fileID**。以不同名称的批量命令包住提取并立即运行历史回收，再撤销、重做，调用与文件仍同步。已撤销且被其他技能引用的模块有文件备份，即使此时被另行删除，重做也能恢复。
- PlayMode 复现：武器骨静止位置为 2、技能位置为 8，基础 Controller 不驱动它。旧实现混出一半仍为 8；新实现分别检查切换与停止的起点、中间、终点，以及自动求值结束后多帧仍为 2、下次施放重新到 8。同时检查 Controller 驱动的手臂回到基础姿势；它切到会驱动武器的状态后，武器也由 Controller 接管。遮罩同数量换路径、全部排除、零时长打断正在衰减的偏移、反复更换装备的骨骼数量均有回归断言。
- Animator 的提示区分两条路径：按键只入队、到段尾才跳；相邻段不 Seek。另有同状态重播提示。窗口早开但段尾晚于混入结束时，不报提前跳转。

## 2026-11-04：拖拽、副本版本与动画归还

- 技能库的折叠列表、虚拟列表和技能大纲共用行内拖拽处理。指针必须在同一行按下，拖拽只启动一次；松手、取消、丢失捕获或行复用后不能沿用旧手势。测试从其他按钮按下再拖过行，另外检查本行阈值、重复移动和行复用。
- 粘贴按来源键和内容版本查找。测试依次粘贴 2 秒效果、将原件改为 6 秒，再取消／选择旧副本／创建新副本；两个版本可共存，回退到 2 秒会找到原版本。内联使用同一套选择。确认文本核对实际 GUID:fileID。没有界面的批处理不会默认同意。
- 调用方的已有环不占用下游模块的八层上限，但环上继承的独立回调约束仍有效。外层事务整体回滚时同步回收已发布的模块文件。引用索引覆盖信号、音频混合器和 ScriptedImporter；先检查磁盘候选，再检查在内存中直接赋值且未保存的引用。没有可订阅的变更事件能涵盖任意 C# 字段赋值，这部分仍随已加载对象增长。
- 普通淡出与惯性混出按技能实际写过的通道记录底姿势；释放时不需要打开原生动画流或检查 Renderer 可见性。测试使用只允许手臂的控制器层：技能把武器移到 8，两种混出在每帧和每四帧更新下，最终连续五帧保持武器为 2、手臂为 5。另外验证 Write Defaults、CullCompletely 恢复、添加／替换／移除控制器，以及手动求值时归还基础姿势。
- 新增实际播放对照：基础控制器完全没有武器曲线；所有状态关闭 Write Defaults 并曾播放过武器曲线；播放中装备脚本更新位置，或只改未动画的坐标轴、旋转和缩放；切换到只动画手臂的技能后，已释放武器仍接受装备的新偏移；混出期间扩展骨架；禁用组件、禁用物体、切换后端、没有 Renderer 时 CullCompletely。用有效 Humanoid Avatar 及实际优化的层级验证普通混出和禁用，先单独运行控制器取基础姿势，再验证技能确实将武器移到 8、退出后恢复原生行为。
- 参数页复用资产行的单次按下手势，跨行拖过不会启动。锁住已提取的模块文件再让外层批处理失败，验证首个编辑异常仍返回调用方、文件错误可见，解锁后仍可清理。私有效果粘贴同时比较来源配置与目标副本配置；一个动作树只询问一次。引用保护覆盖原生 .preset、.signal 容器、.mixer 和自定义导入器资产，测试先检查磁盘依赖，再尝试提取。
- Windows Mono：用 `DisableWriteTypeTree` 构建含副本元数据的效果包，在独立 Windows 测试播放器加载，核对接受过的来源版本、时长策略、时长 7.25 和周期 1.5。结果为 1/1；本轮未为这条用例重建 IL2CPP 播放器。复现时在验证工程启用内置模块 `com.unity.modules.assetbundle`，将环境变量 `GAS_EFFECT_BUNDLE_TEST` 设为独立输出目录。用 `-buildTarget StandaloneWindows64 -executeMethod ZFramework.GAS.Tests.EffectBundleTests.BuildWindowsBundle` 构建，再用同一环境变量运行 `-testPlatform StandaloneWindows64 -testFilter ZFramework.GAS.Tests.EffectBundleTests.StandaloneLoadsEffectWithoutTypeTree`。

## 2026-11-04：禁用、动画交接及文件恢复

- 禁用后继续从 ASC 施放、显式预热、重新启用和 Inspector 通知分别验证；出生时不自动创建播放图。优化骨架测试在最终技能取样与下一次原生 Animator 写入之间读取武器，区分技能确实交还装备位置与原生控制器下一帧覆盖。
- 让 Controller 在三个不同时刻输出不同的手臂位置；第一技能驱动手臂、第二技能只驱动武器，逐次核对 Controller 和技能各自的通道。另在非零时长混出中间扩展骨架，并在真正的动画回调中预热新片段、施放和定位。
- 对同一事务内的多个模块分别制造回滚、Undo、Redo 文件错误；检查其他模块仍重放、失败记录退出日志、无关 Undo 不再删除锁住的文件。Redo 发布失败时可按日志路径找到原模块及 .meta 的备份。
- 在同一角色上保留瞄准并停掉技能：武器先交还基础位置 2，再由装备改为 5.5；连续三帧瞄准跟随新目标且位置保持 5.5。180 个装饰节点、一个受技能控制的武器，实际 Humanoid 与优化骨架均只监视武器。手动图与原生控制器的真实回调里各执行一次动态预热／换片段。
- 更改目标副本和私有子效果后，复用会接受当前配置；来源或目标未再次变化时不再提示。新版本的根与未改动的私有子效果均拥有独立身份；同批首次复制的效果另行确认。粘贴和内联均测试实际引用对象。

## 重做失败后的内容恢复与播放器动态挂点

- 模块重做无法写盘时，失败条目只修复内容，不再发布文件。用带私有子效果的动作模拟失败，核对动作 ID、时长、引用及归属，继续两轮 Undo／Redo，再保存并重新导入技能。另让父模块的文件成功写入却不能加载，验证不会遗留错误文件或写出无主的子模块。
- 模块重做失败后，两轮撤销／重做的每一步都核对技能文件恰好保留两份正在使用的父、子效果；另一用例将父、子副本分离后实际重载脚本域，再次重做时核对两个对象的实例 ID、动作 ID 和引用，最后保存并同步重新导入。
- 在失败后编辑父效果的时长，依次撤销属性编辑和提取、重做提取和属性编辑，再显式保存并重新导入：时长为修改值，子效果仍是原对象。另测外部资产取得子副本时分开私有引用，以及不相关的 Undo 不修复动作槽位、不把旁边的未保存编辑写进文件。
- 动画采样中禁用、启用并只取回驱动，核对旧片段按原时长退出，下一次零混入立刻生效。Generic 角色先预热、再装上新的嵌套挂点并再次预热，核对原有与新增通道的动画和归还。
- 在真正的 OnAnimatorMove 中首次预热并施放，回调内图尚未创建，退出后动画实际生效。手动图回调中核对预热、播放和定位均已排队；故意让一条延迟命令抛错，后续命令仍在同一轮执行。
- 骑士重新启用并在非零混出中途重播，分别取样切换前、起点、中点与终点。Controller 手臂曲线恰好采到旧技能值 14 时仍跟随 Controller；没有手臂曲线的装备写入另用保留瞄准轨的用例检查。
- Windows Mono 播放器加载 Resources 人形角色，用运行时替换的人形片段驱动 Shield：未指定挂点时只跟踪 Shield，额外指定 A 时跟踪两者，退出后归还。覆盖普通与优化骨架，并检查真实位置和监视数。另外从单独构建的内容包加载角色和装备替换表，优化骨架后通过 AnimationTask 施放，检查 Shield 运动及归还；上述三项仍通过。新增运行时构造后端（显式 Shield 加未列出的 RightHand/Weapon）、非零混出期间原地修改同一配置、切换带层遮罩的 Controller；共六项。未运行 Addressables 的目录、远程下载与缓存管理。

编辑器表格保留上一轮的测量结果；本轮重新测量的是下方的运行时数据。编辑器用例的 500 个技能里有 499 个调用同一模块，分为根动作直接调用、条件分支调用、onCancel 内嵌条件调用三种。热编辑打开模块流程，经过真实编辑命令、序列化应用、Undo 记录、调用约束校验和文档同步通知；不含异步绘制。Undo 后首改测 20 次，不把 Undo 自身耗时算进编辑。首次全局内容搜索含建库，超过 200 ms；热技能库搜索、字段编辑、节点拖动分别达到 100 / 50 / 33 ms 的预算。引用保护的首次检查会建磁盘依赖索引，随后随导入增量更新；为保护未保存的改动，每次仍要检查已加载的候选对象。表中的数据针对这个 500 技能的验证工程；已加载的场景组件、原生对象及其依赖数量会影响耗时，不能据此外推到任意规模项目。单独精确检查和实际文件撤销是两组独立的测量，后者包含 Unity Undo 和文件删除，两者不相加。搜索用例执行真实保存、同步重新导入和 Unity Undo，然后检查搜索结果是否反映刚刚发生的修改。表中两项“下一次搜索”只计查询本身，不计磁盘导入和 Undo 操作。冷打开及完整文档撤销仍是可感知开销；拖动不含操作系统输入延迟与 GPU 呈现。

200 单位历史基准的整帧 P95（每帧／每四帧，毫秒）从 **7.08／4.39** 上升到 **17.61／11.30**，上次交付为 **17.67／10.43**。旧数据没有分段计时，也没有同轮对照，不能把那次约 10 ms 的增长精确分摊给某一行代码。

**优化前的分段基线。** 这轮用两组同样的 BasicCombat 骑士交替计时。**每个测量窗口只推进 200 个角色**；两组使用同一 Idle Controller、84 个子 Transform、19 条 Slash 动画路径、相同的 LOD、跳帧姿势保持和 ASC 任务。正式组使用实际骨骼交接；对照组在创建图时省去交接作业和它绑定的句柄。预热 60 帧、测量 120 帧，每一对轮换先跑哪一组。两组都触发 400 次标记、求值 24,000／6,000 次，最后的胸骨姿势相同。本机同时运行了其他播放器，绝对墙钟毫秒不宜直接与历史空闲时的数据相减。

| 200 个单位 | 整帧 P95（ms） | 动画前读取 | Animator.Update | ASC.Tick | 手动求值及保持 |
|---|---:|---:|---:|---:|---:|
| 每帧，正式组 | 29.54 | 4.68 | 4.36 | 0.79 | 16.40 |
| 每帧，对照组 | 20.80 | 0.18 | 3.81 | 0.63 | 5.28 |
| 每四帧，正式组 | 16.39 | 4.64 | 4.35 | 0.70 | 5.94 |
| 每四帧，对照组 | 12.79 | 0.17 | 4.59 | 0.75 | 4.15 |

整帧 P95 沿用原来没有分段探针的循环。后四列是另一次计时的**每帧阶段均值（ms）**，包括读计时器的成本，不应相加当成 P95。逐帧相减的中位数（正式组减对照组）为 **17.72／6.33 ms**，它也不是两个 P95 之差。

Windows 上另用 `QueryThreadCycleTime` 测主线程每帧的周期数，不包括被系统换出时的等待和其他工作线程的 CPU 时间。每帧求值时，相对对照组，**手动求值增加 26.41 百万周期、动画前读取增加 10.71 百万周期**；每四帧求值时，相应差值为 **4.91、10.43 百万周期**。也就是说，两条路径都占成本：每帧播放时交接作业所在的手动求值差异最大；降频后，动画前读取仍对每个单位每帧执行，成为更大的差异。这个循环没有释放中的骨骼，`CaptureNative` 在查询 Controller 片段之前返回；两组保留相同的跳帧 Hold。因此本次对照不能把增长归因于释放期间的 Controller 查询，也没有单独量出某个 SceneHandle 调用的耗时。

每四帧档每帧最多 50 个技能求值。分配单独用正式组测量，两档均为 0 次主线程 GC.Alloc；字节计数探针不可用，记录为 `-1`。这些结论只覆盖预热后的连续播放；不含角色创建、渲染、施放启动、真实释放或首次骨架探测。优化前的完整分段数据保存在 [SkillPerformanceBaseline.json](SkillPerformanceBaseline.json) 的 `runtimeHandoffBefore`。

## 骨骼交接：循环播放优化后

沿用上述两组 200 个骑士和交替计时方法。本轮正式组仍完整启用归还功能；Slash 的 19 条路径均能由基础 Controller 接管。分别在两个采样档断言：200 个单位合计监视 **0 根骨骼**、接入 **0 个交接作业**。正式组与对照组各触发 400 次标记，胸骨姿势一致，每帧／每四帧档的实际求值次数仍为 24,000／6,000。

| 200 个单位 | 整帧 P95（ms） | 动画前读取 | Animator.Update | ASC.Tick | 手动求值及保持 |
|---|---:|---:|---:|---:|---:|
| 每帧，正式组 | 5.97 | 0.03 | 2.71 | 0.34 | 3.13 |
| 每帧，对照组 | 5.92 | 0.03 | 2.71 | 0.33 | 3.04 |
| 每四帧，正式组 | 6.70 | 0.03 | 2.37 | 0.29 | 2.03 |
| 每四帧，对照组 | 6.41 | 0.03 | 2.39 | 0.29 | 2.02 |

同帧配对耗时差的中位数（正式组减对照组），优化前为 **17.72／6.33 ms**，现在为 **-0.012／+0.066 ms**。绝对 P95 也受机器负载影响；正式组与同轮对照的差值才用于判断交接的常驻成本。四个分段列是独立测量的均值。

Windows 主线程动画前读取／手动求值的差值（百万周期／帧，正式组减对照组）：每帧 -0.01／-0.09；每四帧 -0.00／+0.13。两档正式组的主线程 GC.Alloc 调用探针分别为 0／0 次；原始计数、对照及机器信息见 [SkillPerformanceBaseline.json](SkillPerformanceBaseline.json)。

回归：EditMode 257 项、PlayMode 49 项、Windows Mono 独立播放器 7 项通过。用例另行验证：只有 X 曲线的 Controller 不能当作已覆盖整个位置向量；降频的非采样帧修改武器偏移，停止时仍能还给装备；技能播放期间换掉 Controller 会重新监视失去覆盖的骨骼；惯性过渡期间作业会实际接入。基准测的是预热后连续播放，不能外推到独占挂点很多的角色、Humanoid、第一次建图或正在释放骨骼的那几帧。

## 如何复现

1. 从仓库根执行 `dotnet run -c Release --project Tests~/Core/Core.csproj`。独立 Unity 验证工程通过包引用本仓库，并已接入 `Tests~/Editor` 和 `Tests~/PlayMode`；用 BasicCombat 生成器准备场景。
2. 用 Unity Test Runner 跑常规 EditMode 和 PlayMode。规模基准需分别按完整测试名显式运行：`ZFramework.GAS.Editor.Tests.SkillScaleTests.MeasureFiveHundredSkillsAndOneHundredNodes`（EditMode）和 `ZFramework.GAS.Tests.SkillCrowdBenchmarks.TwoHundredUnitsKeepIdenticalGameplayAtBothRates`（PlayMode）。命令行形式为 `Unity.exe -batchmode -projectPath <验证工程> -runTests -testPlatform <EditMode或PlayMode> -testFilter <完整测试名> -testResults <XML路径>`。基准会把 `skill-scale.json` 和 `skill-runtime.json` 写到验证工程的 `GASValidation~`。
3. 用独立验证工程执行 `Unity.exe -projectPath <验证工程> -executeMethod ZFramework.GAS.Editor.Tests.FlowVisualVerification.Run` 获取两张真实窗口截图；这一步需要图形设备。
4. 安装相同 Unity 版本的 Windows IL2CPP 模块及 C++ 构建工具后，从仓库根运行下面的脚本，会构建、启动播放器并检查五次施放后的结果。传入 `-Backend Mono` 可重复独立 Mono 对照。

```powershell
& '.\Tests~\Smoke\WindowsIL2CPP.ps1' -Unity 'C:\Program Files\Unity 6000.3.14f1\Editor\Unity.exe' -ValidationProject 'C:\Users\pc\Testproject\GASRefactorValidation~'
```

5. Android：在装有 Android Build Support、SDK、NDK 和 JDK 的验证工程运行 `Unity.exe -batchmode -quit -buildTarget Android -projectPath <验证工程> -executeMethod ZFramework.GAS.Samples.BasicCombat.Editor.BasicCombatSmokeBuild.AndroidIL2CPP`。产物为 `GASValidation~/Android/GASSmoke.apk`。要实际运行骨骼回归，连接可运行 ARM64 APK 的 Android 设备，使用 `-buildTarget Android -runTests -testPlatform Android -testFilter ResourcesPrefabResolvesLateLoadedReplacementInPlayer -testSettingsFile <settings.json> -testResults <result.xml>`，其中 settings.json 指定 `{"scriptingBackend":"IL2CPP","playerGraphicsAPI":"OpenGLES3"}`。
